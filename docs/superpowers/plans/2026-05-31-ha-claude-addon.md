# HA Claude Code Add-on Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Home Assistant OS add-on that runs a persistent headless Claude Code session with Telegram Channels and Remote Control enabled, connected to Home Assistant via the `hass-mcp` MCP server.

**Architecture:** Alpine-based Docker image (HA add-on base) installs Node.js, Bun, Claude Code, uv, and hass-mcp. On start, an s6 init script validates credentials and writes the MCP config from the Supervisor token. An s6 longrun service then runs `claude --dangerously-skip-permissions --remote-control --channels plugin:telegram@claude-plugins-official` as a supervised daemon. All mutable state (Claude credentials, plugins, session files, Telegram config) lives in `/data` (mounted persistent volume). No web terminal — Remote Control and Telegram are the only interfaces.

**Tech Stack:** Alpine Linux, s6-overlay, Node.js 20, Bun, Claude Code CLI ≥2.1.80, uv, hass-mcp, Home Assistant add-on base image

```dockerfile
# Install Claude Code via official installer
# The installer places the binary at /root/.local/bin/claude
RUN curl -fsSL https://claude.ai/install.sh | sh
# Verify version supports Channels (>=2.1.80)
RUN claude --version 2>&1 | awk -F'[^0-9]*' '{split($0,a,"."); if(a[1]<2 || (a[1]==2 && a[2]<1) || (a[1]==2 && a[2]==1 && a[3]<80)) {print "ERROR: Claude Code version too old for Channels"; exit 1}}'

    /etc/cont-init.d/10-setup.sh \
    /etc/services.d/claude/run \
```

## Task 4: Init Script

**Files:**
- Create: `rootfs/etc/cont-init.d/10-setup.sh`

This script runs once at add-on start (before s6 services). It:
1. Creates required directories in /data
2. Checks for Claude OAuth credentials; starts `claude login` (URL flow) if missing
3. Generates `/data/.claude/mcp.json` from env vars
4. Writes the Telegram bot token to the plugin's expected location

- [ ] **Step 1: Create directory**

```bash
mkdir -p /Users/martin.nuc/programming/hass-claude-code/rootfs/etc/cont-init.d
```

- [ ] **Step 2: Write 10-setup.sh**

```bash
#!/usr/bin/with-contenv bashio
# shellcheck shell=bash
set -euo pipefail

bashio::log.info "Claude Code Agent — running init..."

# ── Directory structure ──────────────────────────────────────────────────────
mkdir -p \
  /data/.claude/channels/telegram \
  /data/.claude/sessions

# ── OAuth credentials ────────────────────────────────────────────────────────
if [[ ! -f "/data/.claude/.credentials.json" ]]; then
  bashio::log.warning "No Claude credentials found."
  bashio::log.warning "Starting 'claude login' — open the URL printed below in a browser."
  bashio::log.warning "Waiting for auth to complete before starting the daemon..."
  # claude login prints a URL and polls for completion
  HOME=/root CLAUDE_CONFIG_DIR=/data/.claude claude login
  bashio::log.info "Login complete."
fi

# ── HA MCP config ────────────────────────────────────────────────────────────
# Use Supervisor-provided token by default; let user override via add-on options
HA_TOKEN="${SUPERVISOR_TOKEN:-}"
if bashio::config.has_value 'ha_token'; then
  HA_TOKEN="$(bashio::config 'ha_token')"
fi

HA_URL="http://supervisor/core"
if bashio::config.has_value 'ha_url'; then
  HA_URL="$(bashio::config 'ha_url')"
fi

if [[ -z "${HA_TOKEN}" ]]; then
  bashio::log.error "No HA token available. Set ha_token in add-on options or ensure hassio_api is enabled."
  exit 1
fi

bashio::log.info "Writing HA MCP config (URL: ${HA_URL})"

cat > /data/.claude/mcp.json << EOF
{
  "mcpServers": {
    "home-assistant": {
      "command": "uvx",
      "args": ["hass-mcp"],
      "env": {
        "HA_TOKEN": "${HA_TOKEN}",
        "HA_URL": "${HA_URL}"
      }
    }
  }
}
EOF
# Permissions: only root can read (contains HA token)
chmod 600 /data/.claude/mcp.json

# ── Telegram bot token ───────────────────────────────────────────────────────
TELEGRAM_BOT_TOKEN="$(bashio::config 'telegram_bot_token')"
if [[ -z "${TELEGRAM_BOT_TOKEN}" ]]; then
  bashio::log.warning "telegram_bot_token is empty. Telegram channel will not connect."
else
  # Claude Code Telegram plugin reads token from this env file
  echo "TELEGRAM_BOT_TOKEN=${TELEGRAM_BOT_TOKEN}" > /data/.claude/channels/telegram/.env
  chmod 600 /data/.claude/channels/telegram/.env
  bashio::log.info "Telegram bot token configured."
fi

bashio::log.info "Init complete."
```

```markdown
# Claude Code Agent — Home Assistant Add-on

Runs a persistent [Claude Code](https://claude.ai/code) session on your Home Assistant OS host,
accessible via **Telegram** (Claude Code Channels) and **Remote Control** (claude.ai or mobile app).
Claude has full read/write access to your Home Assistant via the built-in MCP server.

## Requirements

- Home Assistant OS or Supervised
- Claude Max (or Pro) subscription — a claude.ai account with OAuth login
- Telegram account + a bot token from [@BotFather](https://t.me/BotFather)
- Claude Code v2.1.80+ (installed automatically)
- [Bun](https://bun.sh) — installed in the add-on image automatically

## Installation

1. In Home Assistant, go to **Settings → Add-ons → Add-on Store → ⋮ → Repositories**.
2. Add this repository URL and install **Claude Code Agent**.
3. Configure the add-on options (see below).
4. Start the add-on.

## Configuration

| Option | Required | Default | Description |
|--------|----------|---------|-------------|
| `telegram_bot_token` | Yes | — | Token from [@BotFather](https://t.me/BotFather). Create a bot with `/newbot`. |
| `ha_url` | No | `http://supervisor/core` | Override HA URL (for Container/Core installs only). |
| `ha_token` | No | Auto (Supervisor token) | Override HA long-lived token (for Container/Core installs only). |

## First-Run Setup

### Step 1: Authenticate Claude

On first start, the add-on prints a login URL to its log:

1. Open **Settings → Add-ons → Claude Code Agent → Log**.
2. Copy the URL from the log and open it in a browser.
3. Complete the OAuth flow.
4. The add-on detects completion and starts the daemon automatically.

### Step 2: Enable Remote Control

Once the daemon is running, open [claude.ai/code](https://claude.ai/code) or the Claude mobile app.
Your HA session should appear in the session list with a green dot.

### Step 3: Install the Telegram Channel Plugin

Via Remote Control, type in the claude.ai/code chat:

```
/plugin install telegram@claude-plugins-official
```

Wait for confirmation, then:

```
/reload-plugins
```

Then restart the add-on (Settings → Add-ons → Claude Code Agent → Restart).

### Step 4: Pair Your Telegram Account

1. Open Telegram and send any message to your bot.
2. The bot replies with a pairing code.
3. In Remote Control (claude.ai/code), type:
   ```
   /telegram:access pair <CODE>
   ```
4. Lock the allowlist:
   ```
   /telegram:access policy allowlist
   ```

From now on, only your account can send messages to the bot. The allowlist persists across restarts.

## Security

- **No secrets in the image.** Bot token and HA token are injected at runtime via add-on options; they are never committed to git or baked into the Docker image.
- **`--dangerously-skip-permissions` is intentional.** The add-on runs in a container with only the permissions granted by `config.yaml`. The HA Supervisor token is scoped. All HA config changes are git-committable. The Telegram sender allowlist blocks unknown users.
- **Telegram allowlist.** Only your paired Telegram user ID can send messages. All others are silently dropped.
- **git-backed HA config.** If Claude makes an unwanted change, run `git diff` and `git restore` in your HA config directory.

## Cost

Claude Code with Remote Control and Channels consumes tokens continuously while the session is active. Monitor your usage at [claude.ai/settings/billing](https://claude.ai/settings/billing). An idle session waiting for messages uses minimal tokens.

## Troubleshooting

**Daemon won't start / exits immediately:**
Check the add-on log. If you see "No Claude credentials found", the OAuth login did not complete. Restart the add-on and follow Step 1 again.

**Telegram bot doesn't respond:**
Ensure the add-on is running and you've completed Steps 3 and 4. Check the log for "channel could not register" — this means the plugin isn't installed yet.

**Remote Control session not visible:**
Ensure you're logged into claude.ai with the same account used in the add-on. The session may take ~30 seconds to appear after add-on start.

**Permission errors on HA actions:**
The Supervisor token has broad HA access by default. If you override `ha_token`, ensure it has the required scopes.
```

## Post-Build: First-Run Flow Summary

```
Add-on start
  └─ cont-init.d/10-setup.sh
       ├─ /data/.claude/ dirs created
       ├─ No credentials? → runs `claude login`, prints URL to log
       ├─ Writes /data/.claude/mcp.json  (HA MCP server config, mode 600)
       └─ Writes /data/.claude/channels/telegram/.env  (bot token, mode 600)
  └─ services.d/claude/run → /app/start.sh
       └─ exec claude --dangerously-skip-permissions --remote-control
                       --channels plugin:telegram@claude-plugins-official
                       (channel logs warning if plugin not yet installed)

User actions (one-time):
  1. Open URL from log → complete OAuth
  2. Open claude.ai/code → session appears
  3. /plugin install telegram@claude-plugins-official → restart add-on
  4. Message bot → get pairing code → /telegram:access pair <code>
  5. /telegram:access policy allowlist

Ongoing:
  Telegram message → Claude reacts → replies in Telegram
  claude.ai/code or Claude mobile → Remote Control → full session
  s6 restarts daemon on crash (credentials + plugins persist in /data)
```
